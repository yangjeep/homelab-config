# Company native permission guard

Install this directory as the root-owned `leaselab-company-guard` plugin in each of the seven profiles. No role SSH account may write it, profile configuration, central Hermes state, or SSH keys. Only trusted launchers/dispatchers set `HERMES_PROFILE`; missing/unknown roles deny everything. Run one profile per process; same-process profile multiplexing is unsupported.

CoS has native learning, coordinator Kanban, scoped GitHub and management tools; no terminal/file execution. Only CoS may call `kanban_create`, and its native `args.assignee` must exactly name one of the seven company profiles: `chief-of-staff`, `support`, `sre`, `engineer`, `reviewer`, `qa-security`, or `growth`. Missing, malformed, unknown, and `default` assignments are blocked before the native tool can create a dispatcher task. Specialists add the five native terminal/file tools only when the effective Hermes backend resolves to SSH at `127.0.0.1:22`, user `leaselab-<role>`, key `/etc/leaselab-company/ssh/<role>`. The resolver honors native per-turn terminal scopes. Worker Kanban grants exclude orchestrator create/list/unblock. Names are pinned to upstream `1a990f30628c25fb83d29c4d3b3d18dcb085406e`. Unknown tools, process bridges, execute_code, delegation, browser, web-fetch plugins, external plugin installation and all MCP tools are denied. Add future company MCP tools individually only after review.

This is a native tool-dispatch veto, not a Python sandbox. The host hook loader can fail open when a plugin is absent, fails registration, or raises outside the protected resolver boundary. This upstream revision fails closed on pre-tool hook timeouts. Deployment must verify actual denied calls before enabling a profile, and again after Hermes upgrades. Keep profiles/plugins fixed for the lifetime of a process; restart after configuration changes to discard native terminal/file caches. Tests exercise the callback, not a deployed SSH boundary.

All Hermes processes still run as trusted `hermes`. Native memory/skills/session/Kanban tools run in that UID. Terminal/file execution relies on separate restricted Unix SSH users: no central `/home/hermes`, `/var/lib/leaselab-company`, board DB, other role home, privileged socket, broad sudo, or cross-role keys. SSH host-key verification and role filesystem permissions must be tested on the deployed host. Terminal permission is arbitrary shell execution as that role; support/growth/reviewer read-only constraints require repository/service credential scopes and filesystem permissions, not this allowlist. Keep credentials provisioned inside each role account; do not supply shared host secrets through terminal environment forwarding.

Local verification: `uv run --with pytest --with pydantic pytest -q ../tests/test_guard.py` and `uv run --with basedpyright basedpyright -p pyrightconfig.json`. The narrow typing stub declares only the five native resolver fields consumed here; it is not runtime code. Type checking uses all diagnostics except missing runtime source (Hermes installs separately) and private native API access (the verified shared resolver is private). Reverify the stub and resolver on upgrades.
