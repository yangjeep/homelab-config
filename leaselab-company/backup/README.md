# LeaseLab Hermes dual backup

Adapted from the live Homelab LXC913 `/usr/local/sbin/hermes-knowledge-backup` and `hermes-full-backup` inspected 2026-09-15, not the older installer that included backup SSH keys. LeaseLab is LXC916 (`192.168.253.217`). No Hermes fork or new service stack.

## Jobs and data

* Hourly `leaselab-knowledge-backup`: `/var/lib/leaselab-company/profiles/*/{config.yaml,profile.yaml,SOUL.md,AGENTS.md,notes,memory,memories,skills}` through text extension allowlist and `excludes`. Seven required role profiles must be present. Fixed root-owned gitleaks configuration scans candidate, exact staged tree and complete Git history before push. Any scanner error rejects the entire snapshot. No secret redaction. Target `yangjeep/hermes-leaselab`, `main`, dedicated SSH deploy key. It is a generated backup repository; do not edit it as an engineering source repository.
* Daily 03:30 (system timezone, five-minute jitter, persistent): native `hermes backup` with `HERMES_HOME=/var/lib/leaselab-company`, plus explicit host wiring, version, code SHA and patch, SHA256 manifest, gzip tar, SSH rsync. The installed CLI resolves any custom profile home to the company root: one native `hermes.zip` contains all seven profiles, root Kanban state/board metadata, `kanban.db` and `shared-state.db`. Hermes uses SQLite online backup for every `.db` and excludes live WAL/SHM/journal sidecars. Validation requires all seven `state.db`, config and SOUL files, company databases, ZIP CRC and integrity_check for every archived database. Snapshots are individually consistent, not one cross-database transaction. No `.sqlite` files existed at inspection; introducing one makes the job fail until its online-copy rule is added.

Runtime profiles: `chief-of-staff`, `engineer`, `qa-security`, `reviewer`, `sre`, `support`, `growth`. Native implementation inspected at `/home/hermes/.hermes/hermes-agent/hermes_cli/backup.py` and `hermes_constants.py`.

Git excludes `.env*`, credential/auth/token/secret filenames, private key formats, `.ssh`, raw databases, sessions, logs, caches, archives, runtime/state trees and symlinks. Config files are copied unchanged then scanned, so a secret-bearing config stops Git backup instead of silently removing configuration. Gitleaks is detection, not a formal guarantee against every possible secret encoding; root-owned allowlists and target identities remain essential controls.

## Full archive secret policy

The existing native policy explicitly **includes** `.env`, `auth.json`, session/state databases and native `vault.key`/`vault.json.enc`; browser-profile credential snapshots and live browser profiles are excluded, as are code/dependencies/caches, prior backups, nonregular files and symlinks. It is not a secret-free ZIP. This implementation preserves that policy for the company root. It rejects native `_external` entries to prevent memory-provider expansion outside that root.

TrueNAS backups are **unencrypted** like the existing Homelab design. Protection is SSH in transit, owner-only files/directories, a dedicated restricted upload account, and NAS dataset access controls. Do not put the full archive in GitHub. Dedicated backup SSH private keys stay only in `/var/lib/leaselab-backup/keys`, which is never archived. `/srv/leaselab/roles` and `/etc/leaselab-company/ssh` are never broadly copied: coding OAuth credentials, Google service-account credentials and role SSH keys must be re-provisioned from their authoritative secret source after disaster recovery. `/etc/leaselab-backup` must remain policy/public-hostkeys only; do not store secrets there.

## Provision and activate after review

1. Install prerequisites on LXC916: bash, coreutils, util-linux, git, rsync, python3 and the reviewed gitleaks binary/version used in LXC913. Existing Hermes CLI must remain functional as `hermes`. Run `bash install.sh` from this directory as root. It installs files but does not enable timers.
2. Provision unique owner-only keys at `/var/lib/leaselab-backup/keys/github_ed25519` and `truenas_ed25519`; register only the GitHub key as write deploy key on `yangjeep/hermes-leaselab`. Store private recovery material in the approved secret system, never in this directory or repo.
3. Provision TrueNAS `192.168.253.100` account `hermes-agent-leaselab-backup`, owner-only `/mnt/main/homelab/backup/hermes-agent-leaselab/archives`. Follow existing TrueNAS `midclt` account pattern with authorized-key options `restrict,from="192.168.253.217",command="/usr/bin/rrsync -wo -no-del -munge /mnt/main/homelab/backup/hermes-agent-leaselab/archives"`; enforce the same ForceCommand, disabled forwarding/TTY/password login through SSH Match User configuration. Do not reuse Homelab's confined identity. Do not grant delete or shell access. NAS owns retention; sender never deletes remote backups.
4. Install independently verified NAS and GitHub host keys into `/etc/leaselab-backup/known_hosts` (0600). `ssh_config` pins strict host checking; GitHub uses `ssh.github.com:443` with HostKeyAlias `github.com`. No TOFU bypass.
5. Initialize or clone `/var/lib/leaselab-backup/repo`, with branch `main`, Git identity, and exact remote `git@leaselab-github:yangjeep/hermes-leaselab.git`, using `GIT_SSH_COMMAND='ssh -F /etc/leaselab-backup/ssh_config'`. Directory 0700, root-owned. No force push. A failed earlier push is retried even if content is unchanged.
6. Run both jobs manually, verify the Git commit and NAS archive independently, run an isolated restore drill, then `systemctl enable --now leaselab-knowledge-backup.timer leaselab-full-backup.timer`. Inspect `systemctl list-timers` and job journals. No live deployment or credentials are bundled here.

## Restore smoke and validation

`python3 verify.py /secure/path/hermes.zip` checks paths, CRC, required files and SQLite integrity using a fresh temporary directory; it never writes to active state. For a full drill, retrieve the archive using a separate NAS administrator identity (the upload-only account cannot download), verify gzip tar and `SHA256SUMS`, then run `hermes import` only inside a disposable LXC with a fresh Hermes root and gateway/timers disabled. Re-provision secret identities and host wiring selectively before enabling any external integration. Never extract over a running company deployment.

Tests: `uv run --with pytest pytest -q tests/test_backup.py`; the scanner fixture requires Linux + gitleaks. `bash tests/test_backup_candidate.sh "$PWD/backup"` directly exercises production candidate generation with real files, a synthetic secret, and overlap/symlink rejection. The isolated fixture passed on LXC913's real scanner; archive validation/corruption/path tests passed locally. No NAS upload, Git push, live restore or timer activation has been performed by these fixtures.
